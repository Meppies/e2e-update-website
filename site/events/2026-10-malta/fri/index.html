EUC for the Agentic Enterprise - The Workspace as a Secure Execution Layer for Agentic AI (intro)

Jeremy Ingram

Enterprises spent years and significant capital building sophisticated EUC and VDI estates. As remote-work patterns normalized, SaaS adoption accelerated, renewal pressures increased, and alternative application and desktop delivery models matured, many organizations began to reassess the long-term strategic role of those environments.

Agentic AI should force organizations to reassess the value of their existing EUC platforms and the role those platforms can play in the controlled integration of autonomous agents into the enterprise.

This does not remove the need to modernize authentication, migrate appropriate services out of legacy data centers, improve data governance, or address technical debt. In fact, agentic AI makes those modernization efforts more important. But many of the architectural and operational principles required to run EUC well controlled execution, identity-based access, application entitlement, isolation, policy enforcement, observability, lifecycle management, and operational accountability closely resemble the disciplines enterprises will need when introducing autonomous software.

At the same time, the EUC ecosystem itself is evolving. Agent identities, managed execution environments, Conditional Access for agents, MCP gateways, Cloud PCs for agents, and AI-specific policy controls are beginning to blur the line between the traditional user workspace and a governed execution environment for software actors.

This session explores whether mature EUC architecture can provide a practical starting point for secure agentic AI adoption. We will examine what translates well, what does not, and what still needs to be modernized before agents can be introduced safely at enterprise scale.

Attendees will leave with an understanding of how agentic AI changes familiar EUC assumptions around identity, execution, applications, data, and trust. The session will explore how established EUC design principles may translate into agent governance; where Citrix, Windows 365, AVD, Horizon, and similar platforms could play a role as controlled execution environments; why legacy applications may keep EUC relevant in an agentic world; and what still has to change across authentication, data governance, DLP, observability, lifecycle management, and cloud architecture.

About Jeremy Ingram

Jeremy is a Consulting Architect with Ferroque Systems, specializing in Citrix virtualization and networking, modern workspace architecture, application and desktop delivery, identity modernization, and cloud transformation. He has worked in end-user computing since 2008 and joined Ferroque Systems in 2020. Stop Giving AI Agents Your Desktop (intro session)

Denis Gundarev

The dominant CUA architecture — agent -> VM -> screenshot -> mouse — treats the agent as a very fast remote employee. But remote computing spent three decades building the primitives agents actually need: session brokering, isolation, process and window ownership, input routing, graphics capture, auditing, and human shadowing. This talk reframes MCP as the control plane over session infrastructure, not the runtime itself. Drawing on lessons from building Vedon, an experimental desktop execution stack for computer-use agents, I'll cover multi-session orchestration, browser attachment, agent/human coexistence, and why VDI-style infrastructure — far from being obsolete — may become the substrate agents run on.

About Denis Gundarev

Denis has over 25 years of experience in EUC, VDI, remote computing, and desktop operating systems, with a background spanning Citrix, VMware, AWS, and Microsoft. His work focuses on remoting protocols, session infrastructure, graphics, SDKs, and computer-use agents, especially making desktop environments reliable for both humans and AI.
